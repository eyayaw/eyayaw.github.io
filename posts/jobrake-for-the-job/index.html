jobrake for the job

jobrake

A simple CLI tool & Python package for raking job postings off LinkedIn & Indeed
Author

Eyayaw Beze

Published

September 7, 2026

I’ve been looking for a simple tool for getting new job postings from job boards, because I was tired of doomscrolling on the LinkedIn Jobs tab. Oh yeah, [sg]etting job alerts is equally overwhelming.1

Who to blame, but I’ve not found any that is “reliable”, simple, and free.2

Tip

I spend bonkers amount of time trying to “automate” my job search, but less on actually searching. So, heed my advice on this matter. 😅

So jobrake () is an ambitious attempt to address these challenges.

It’s a simple CLI tool and Python package that fetches job postings from Indeed and LinkedIn and returns every result as the same small Job dictionary. There is no login, no browser automation, just simple requests via httpx.

I intend jobrake to be simple and light3. It searches, normalizes, and returns jobs. That is it. It helps you swing the rake at the big piles—LinkedIn and Indeed. So, currently, it does not support other boards such as Glassdoor or ZipRecruiter.

Installation

jobrake is not on PyPI so install it from GitHub with uv. Please read the installation guides for your system.

I assume unix-based systems hereafter, sorry Windows-(or dare I say WSL-) people, you’re on your own—read the uv docs, adapt all the code wherever necessary; you can do it!

I personally use jobrake through the CLI, so you can install it as a tool, too. uv installs jobrake and adds it to your ${PATH}.

uv tool install git+https://github.com/eyayaw/jobrake
# For ephemeral use
# uvx git+https://github.com/eyayaw/jobrake

A first rake

Say you’re an economist looking for data science roles in the Netherlands, just like me4.

Code 
jobrake linkedin \
        --query "economist OR data scientist" \
        --location "amsterdam, netherlands" \
        --max-age 24 \
        --results 5 \
        --output data/jobs-linkedin.csv \
        --details 2>/dev/null
Code 
jobrake indeed \
        -q "economist OR data scientist" \
        -c "netherlands" \
        -l "amsterdam" \
        -a 24 \
        -n 5 \
        -o data/jobs-indeed.json 2>/dev/null

Note: If you’re new to CLI lingo, left and right are the same interface twice: long flags spelled out for LinkedIn, and their short aliases for Indeed. Remove the redirect (2>/dev/null) to see progress updates and other info.

Descriptions and other details

Every job result includes the same identity and summary fields, with null for unavailable summary values. Detail fields appear only when the job board supplies a value5. This keeps the common fields predictable, while keeping optional details compact.

The two sites differ in how much info they display upfront. Indeed includes every supported detail field in its search results. However, LinkedIn search cards contain only basic summaries, so jobrake “hydrates” them—fetches each posting page—when you ask for details such as the job description with --details | -d:

jobrake linkedin \
  -q "economist" \
  -l "amsterdam, north holland, netherlands" \
  -d

The difference also affects speed. Indeed searches are fast because we use its mobile app API. LinkedIn’s guest search API is rate-limited, so jobrake uses a token bucket to pace requests. The LinkedIn scraper takes longer by design, so keep blinking at the progress bar.6

jobrake caches fetched details in your user cache directory. Repeated searches can reuse those details. If the cache is missing or damaged, jobrake fetches them again. Use --no-cache to disable caching.

Using jobrake from Python

Add it to your project dependencies with uv.

# create a .venv (uv venv .venv) or init a project uv init
uv add git+https://github.com/eyayaw/jobrake

The package entry point is asynchronous:

import asyncio

from jobrake import scrape


async def main():
    jobs = await scrape(
        "indeed",
        query="data scientist",
        country="netherlands",
        location="amsterdam",
        results=10,
    )

    for job in jobs:
        print(job["date"], job["title"], job["company"])

asyncio.run(main())

What if …?

WarningA caveat

Breaking in no time: Scrapers do not make promises, right? 🙃 jobrake pings unofficial(ly) (api) endpoints and relies on small HTML markups, so it lives at the mercy of LinkedIn and Indeed. Changes of API endpoints or markups can break it any day. If a request fails, it’s probably them, not us. File an issue, and offer fixes.

The code is available at github.com/eyayaw/jobrake.

Happy searching, I mean, raking!

Appendix

Output formats

Explicit output-format selection:

jobrake ... --format json
jobrake ... -f jsonl
jobrake ... -f csv

Files still infer their format from the extension.

jobrake ... -o jobs.csv
jobrake ... -o jobs.jsonl

An explicit --format overrides that inference, i.e., you can do -f jsonl -o jobs.txt but you get JSON Lines in a .txt file.

Place name resolution

jobrake can also resolve place names from the CLI. LinkedIn needs an unambiguous location to return results. Look up the place first, then use its display name in your search:

jobrake places linkedin "amsterdam"
# Then search with -l "Amsterdam, North Holland, Netherlands"

For Indeed, include the country:

jobrake places indeed -c netherlands "amsterdam"
